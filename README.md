# perm-monitor

Сбор данных с открытого API и поиск новых записей по фильтру региона.

## Файлы

| Файл | Назначение |
|---|---|
| `monitor_perm.py` | Скрипт. Стандартная библиотека Python, внешних пакетов нет. |
| `found_objects.txt` | Журнал: дата, метка (`базовая линия` / `НОВЫЙ`), данные записи. |
| `seen_ids.json` | Уже обработанные ID. Не удалять. |
| `seen_groups.json` | Известные новостройки (застройщик + название + адрес). Не удалять. |
| `tg_state.json` | Позиция чтения обновлений Telegram и замеченные незнакомцы. Не удалять. |
| `heartbeat.txt` | Суточная отметка; держит расписание включённым. |
| `.github/workflows/monitor.yml` | Расписание и сохранение состояния. |

## Запуск

~~~bash
python3 monitor_perm.py              # полный проход
python3 monitor_perm.py --quick      # только свежие записи
python3 monitor_perm.py --test-send  # карточка последней новостройки в Telegram
./check.sh                           # прогон + последние 5 строк журнала
~~~

## Расписание

- `*/5 * * * *` — быстрый режим, 3 страницы API; если появилось новое, скрипт сам
  делает полный проход.
- `12 3 * * *` — полный проход раз в сутки.
- Состояние коммитится после прогона; раз в сутки дописывается `heartbeat.txt`.
- GitHub может задерживать запуск по расписанию на 5–20 минут.

## Telegram

- Уведомления — если заданы секреты `TG_TOKEN` и `TG_CHAT_ID`.
- Карточка: название ЖК жирным, адрес, застройщик, при нескольких корпусах — их число
  и ID, ссылка на карточку объекта
  (`https://наш.дом.рф/сервисы/каталог-новостроек/объект/<ID>`;
  превью ссылки Telegram не получит — сайт закрыт антиботом).
- Фотографии не отправляются.
- Бот приватный: карточки и приветствие уходят только в разрешённые чаты —
  `TG_CHAT_ID` (владелец) и перечисленные через запятую в `TG_CHAT_IDS`.
- Всем остальным на любое сообщение бот отвечает «Этот бот приватный.», а владельцу
  один раз присылает уведомление с именем и id незнакомого чата (id хранится в
  `tg_state.json`). Чтобы выдать доступ, id добавляется в секрет `TG_CHAT_IDS`;
  чтобы отозвать — удаляется оттуда.
- На `/start` разрешённый чат получает приветствие с примером карточки —
  это последняя новостройка в списке на момент ответа.
- Обновления (`getUpdates`) читаются в каждом прогоне, поэтому ответ на `/start`
  приходит в течение нескольких минут (зависит от задержки расписания).
- Ручной запуск с input `greeting` присылает приветствие тому же чату.
