# Мониторинг новостроек Пермского края (наш.дом.рф)

Следит за появлением **новых строящихся объектов** в Пермском крае на портале
[наш.дом.рф](https://наш.дом.рф/новостройки/строящиеся/пермский-край/)
и записывает найденное в журнал с датой обнаружения. Работает в облаке —
на бесплатном расписании GitHub Actions, без своего сервера и без куков.

## Как это работает

1. Скрипт обращается к открытому API портала: `.../сервисы/api/kn/object`.
   Cookies, вход и антибот не нужны: данные открытые.
2. API **не умеет фильтровать по региону** и отдаёт по 50 записей на страницу,
   поэтому скрипт параллельно скачивает все ~268 страниц (≈13 400 объектов)
   и оставляет только объекты Пермского края (`rpdRegionCd == 59`).
3. Результат сравнивается со списком уже увиденных ID (`seen_ids.json`).
4. Новые объекты дописываются в `found_objects.txt` с датой и меткой `НОВЫЙ`,
   и уходят в Telegram (если настроен).

> Сайт закрыт антиботом ServicePipe (JS-челлендж), поэтому HTML-страницу
> парсить напрямую не получается. API этого барьера не использует.

Скрипт на чистой стандартной библиотеке Python — `requests` и прочие пакеты
не нужны. Прогон занимает 20–60 секунд.

## Файлы

| Файл | Назначение |
|---|---|
| `monitor_perm.py` | Основной скрипт проверки. |
| `found_objects.txt` | Журнал находок: дата, метка, ID, дата публикации, срок ввода, застройщик, адрес. Метки: `базовая линия` (первый прогон) и `НОВЫЙ`. |
| `seen_ids.json` | Технический список уже увиденных `objId`. **Не удалять** — иначе следующий прогон занесёт всё как «базовую линию». |
| `heartbeat.txt` | Пульс: дата последнего суточного коммита; заодно держит расписание включённым. |
| `.github/workflows/monitor.yml` | Расписание и сохранение состояния. |

## Запуск в GitHub Actions

- Публичный репозиторий, стандартные раннеры — **бесплатно и без лимита минут**.
- Расписание: каждый час в `:07` UTC (`cron: "7 * * * *"`). Не в начале часа:
  там очередь GitHub и задержки.
- После каждого прогона workflow коммитит `seen_ids.json` и `found_objects.txt`,
  если они изменились.
- Публичный репозиторий GitHub отключает расписание после 60 дней без
  активности, а прогоны по расписанию активностью не считаются. Поэтому раз в сутки
  workflow дописывает строку в `heartbeat.txt` — это и активность, и видимый пульс.
- Ручной запуск: вкладка Actions → «Мониторинг новостроек Пермского края» →
  Run workflow, или `gh workflow run monitor.yml`.

### Уведомления в Telegram

1. В Telegram у `@BotFather` — `/newbot`, получить токен.
2. Написать боту любое сообщение, затем узнать chat_id:
   `curl -s "https://api.telegram.org/bot<ТОКЕН>/getUpdates"` — в ответе `"chat":{"id": …}`.
3. В репозитории: Settings → Secrets and variables → Actions → два секрета
   `TG_TOKEN` и `TG_CHAT_ID`.

Без секретов скрипт работает молча и просто пишет журнал.

## Запуск локально

~~~bash
cd ~/projects/perm-monitor
python3 monitor_perm.py          # только проверка
./check.sh                       # проверка + последние 5 строк журнала
~~~

Локальный прогон меняет те же `seen_ids.json` и `found_objects.txt`, что и облако:
если запустить вручную, следующие находки облако уже не увидит — оно возьмёт
список из репозитория. Для ручной проверки лучше `git pull`, потом прогон, потом
`git commit && git push`.

Уведомления локально:

~~~bash
TG_TOKEN="123456:AAEh..." TG_CHAT_ID="111222333" python3 monitor_perm.py
~~~

## Ограничения

- Расписание GitHub — «лучшее из возможного»: в пик запуск может опоздать на
  5–30 минут. Для новостроек это не важно.
- Часовой прогон — 24 запуска в сутки; каждый обновляет до 268 страниц API.
  Будьте вежливы к порталу: не снижайте интервал без нужды.
